# [Feature] 另开分支时补全记忆，并停用 replace 版的隐藏楼层

### 这个能力解决什么问题？

楼层 / 角色记忆

上下文快满的时候，实际的做法一直是「另开分支」：砍掉前面的楼层开一个新会话。
被砍掉的楼层留在旧会话里读得到，但新会话的角色看不到它们——除非那些内容已经在
记忆里。现在要靠手动：导出聊天 → 自己总结成记忆 → 导入，再分支。

同一个面板上的「隐藏楼层」做的是类似的事，但它用 `replace` 直接改写当前会话，
不可还原，也不会留下任何记忆。

### 期望的行为

把「另开分支」和记忆结合起来，一个流程做完：

1. 在楼层面板选好从第几层开始分支
2. 由子 Agent 读**目前保留的全部聊天记录**和全部记忆，把还没进记忆的事件接着记下去
3. 算完之后**先给玩家看**有哪些插入项，再决定要不要带过去
4. 不满意时，玩家可以**自己加一段提示词重新补全**
5. 确认后创建分支，新会话带着补全后的记忆

同时**停用**原本单纯用 `replace` 实现的隐藏楼层。

### 记忆的格式

1. 用时间当标题，例如 `【2025/10/01 08:00:00~16:00:00】`、
   `【圣龙曆852年4月28日 12:00 ~ 圣龙曆852年4月30日 18:00】`
2. 一个条目至少包括一整天，也可能由多天组成，由场景事件的密度而定
3. 一个条目里有多个场景事件
4. 场景事件的开头也都标出时间，然后用约 20~50 字描述事件
5. 记录的都是还没记忆过的事件，所以要把所有记忆和聊天记录都给 AI 读，让它知道从哪里
   继续记录

### 读哪些聊天记录

例如玩到第 150 层需要记忆了，之前的记忆记到第 100 层，前 50 层早就被裁切掉。这时应该拿
第 50~150 层的聊天记录，和所有记忆一起让 AI 判断从哪里接续；AI 新写出来的记忆范围应该是
第 100~150 层。

### 长度

程序的限制放在 1500 字，但指引 AI 的字数保持不变；事件过多时允许舍弃描述细节来缩减字数。
