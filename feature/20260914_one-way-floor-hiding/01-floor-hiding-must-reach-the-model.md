# [Bug/Feature] 隐藏楼层没有真正生效；改成不可还原的单向操作

### 现象

隐藏楼层之后：

- 被隐藏的楼层**仍然留在聊天画面上**，保留下来的玩家楼层还会重复一次
- 「上下文已用」不但没降，反而**涨了**
- 模型实际收到的上下文**也没有变小**

实测（session `西幻-格溫德琳 TEST`，隐藏 50 层）：

| | 隐藏前 | 隐藏后 |
| --- | --- | --- |
| 实际 prompt（provider 报的 uncached + cacheRead） | 122,075 | **188,245** |
| 原始 surface | 78 节点 / 95,915 字 | 105 节点 / 140,077 字 |
| Agent RP overlay（本该发出去的） | 74 节点 | 26 节点 / 41,813 字 |

世界书占用在两轮之间几乎没变（30,808 → 37,347），所以涨的是对话历史本身。

### 为什么

0.1.1 时隐藏楼层下的是真正的 surface `replace`，`session.surface.nodes` 真的少掉
那些节点，下游（模型请求、token meter、画面）**全部免费跟上**。

0.1.3 适配时改成了 `append` + `agent-rp/surface-override`，而那是一个
**ignorable 插件事件**——只有 Agent RP 自己调用 `roleplaySurfaceNodes()` /
`roleplayModelHistory()` 的地方认得它。DSH 的三个消费端都不认：

| 消费端 | 认得吗 |
| --- | --- |
| 送给模型的 messages | ✘ 只在 prompt-regex 那一轮真的替换过时才换成 overlay 版 |
| 上下文已用（token meter） | ✘ 完全没有接缝 |
| 聊天画面（append-origin transcript） | ✘ 靠显示计划，而那条规则被收窄过 |

所以隐藏楼层只改到了「Agent RP 自己看的那一层」，而副本是净增加的——上下文因此变大。

### 期望的行为

1. 隐藏之后，模型**真的**收不到那些楼层
2. 「上下文已用」跟着降
3. 画面上被隐藏的楼层消失，保留的楼层不重复
4. 隐藏**不允许还原**，改成在隐藏前提醒一次

### 补充：为什么可以改回真正的 `replace`

当初改成 overlay 的理由是：`assistant/message` 不能带 `sourceEventSeqs`，而 `replace`
必须声明它遮蔽的每一个节点，所以**助手消息不能当取代者**。

但隐藏楼层的取代者**不需要是助手消息**——它只是一个标记。`user/message` 可以带
`sourceEventSeqs`，DSH 自己的 compaction 用的正是这个写法。重新生成那条路必须restate
助手回复，所以它仍然只能用 overlay；隐藏楼层当初只是被顺手一起搬过去了。

### 补充：为什么不允许还原反而更干净

`replace` 没有反向操作。唯一的还原方式是把整条 surface 重写一遍，那也正是这个机制
**唯一做不到的事**。不允许还原之后：

- 隐藏变成单调的，surface 永远只有 `[标记, ...可见楼层]` 一种形状，标记不会累积
- 少掉一个真实危险：原本缩小范围是「先全部还原、再重新隐藏」两条独立命令，第一条成功
  第二条失败时会**静默还原掉玩家已经提交的隐藏**

**内容并没有消失**：它留在 SessionLog、留在 `hiddenPrefix`，所以楼层面板和「导出聊天」
都还读得到，只是回不到模型的上下文里。确认窗应该这样写，而不是写成「将永久删除」。
