# [Feature] 会话级正则：每段会话有自己的一份，可编辑，分支带走

### 这个能力解决什么问题？

正则

正则来自四个地方——角色卡、预设、正则包、Tavern Helper 脚本——但**没有任何
「这段会话自己的」可编辑层**。想为某一段对话调一条规则，只能去改角色库里的卡，
而那会影响到所有会话。

而且有一个没人注意到的破口：**纯显示正则读的是角色库的即时版本**。在角色库改一条
显示正则，**所有已经开始的会话的画面都会跟着变**——提示词正则是冻结的，显示正则不是。

### 期望的行为

1. 每段会话有自己的正则，角色卡与正则包在创建会话时形成快照
2. 分支时正则一起分支
3. 能编辑每段会话的正则
4. 正则只在正确的时机应用，不要在模型吐字时不停重跑影响性能

### 补充：调查结论

**字段本来就齐了。** `ImportedRegexScript` 已经是完整的 SillyTavern 形状：
`placement`（扫描对象：1 玩家 / 2 角色）、`markdownOnly` 与 `promptOnly`（作用阶段）、
`minDepth` / `maxDepth`（**扫描深度**）、`trimStrings`、`substituteRegex`、`runOnEdit`。
缺的不是字段，是编辑入口。

**快照本来就成立。** 角色卡、预设、正则包都已经是会话事件里的快照。唯一的例外就是
上面那个显示正则的 live 破口。

**分支不用写代码。** 实测 VM 上 20 个有 `parentSession` 的 session，
`agent-rp/*-seed` 全部都会被带进子 session。覆盖层是 durable session record，
所以同一个机制自动生效。

### 补充：性能问题的真正成因

三层浪费叠在一起：

1. `MutationObserver(subtree)` 让串流的每个 chunk 都触发一次 rAF 扫描
2. 扫描会走过画面上**每一列**，每列重跑一次显示正则，而 `compileRegex()`
   **没有任何缓存**——每一列每一条规则每一帧都 `new RegExp()`
3. 之后还要 `JSON.stringify` 一个大对象算签名才知道要不要重挂

提示词那侧没有问题：它挂在 `llm/stream`，本来就是每请求一次。
