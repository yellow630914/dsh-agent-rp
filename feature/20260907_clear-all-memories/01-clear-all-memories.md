# [Feature] 一次清空全部会话记忆，并在删除的同时导出

### 这个能力解决什么问题？

角色记忆

记忆管理里只能一条一条「忘记」。想重来一遍——换个方向继续玩、或者把一段试玩
积累的记忆整批丢掉——就得点很多次，而且中途没有任何东西可以留底。

### 期望的行为

记忆管理对话框里、「导出」「导入」**左边**新增一个清空按钮：

1. 点击后**弹出确认窗**，不能一下手就清掉
2. 确认后，**在删除的同时把这些记忆导出成文件**
3. 清空当前全部有效记忆

### 为什么删除时必须导出

会话历史只能追加，删除之后**没有撤销**。那份导出文件是唯一的恢复途径，
而且它和「导入」是同一个格式，可以直接放回来。

所以导出不是附带的贴心功能，是这个操作的安全网——因此它内建在流程里，
而不是让人记得先自己点一次「导出」。

### 补充：采用的实现

`/rp-memory` 新增 `operation: 'forget-all'`，与
[导入](../20260901_migration-worlds-and-memory-io/02-session-memory-export-import.md)
同一个形状：**一条 `command/done` 记录整件事**，而不是发 N 条 forget。

理由和导入一样：一次 `command/run` + 一次 `command/done`，要么全清、要么什么都
没发生，没有半清空的中间状态需要收拾。日志里也只留一句「这里清空过」，
而不是一串逐条 forget 把真正的历史淹掉。

请求没有任何字段（只有 `format` 与 `operation`），并且沿用了写入前自检——
和其他四种操作一样，先用真正的 `readAgentRpMemoryHistory()` 折一遍、
确认有效记忆数量变成 0，才让记录落盘。

`applyCommandRecord()` 的 `forget-all` 分支只做 `active.clear()` 并返回空数组：
**清空不创建任何记录**，所以时间顺序的 `history.all` 完全不受影响——
曾经记住过什么、后来又清掉了，都还replay得出来。

没有可清空的记忆时命令直接拒绝，避免留下一条什么都没做的记录。

### 补充：界面

「清空」放在「导出」左边，用危险色，没有记忆时禁用。点击弹出确认窗，
窗里写明会删除几条、会先导出、以及删除之后没有撤销。

确认按钮的文案是「**导出并清空**」而不是「确定」——按钮本身就该说清楚它会做两件事。

导出在删除之前执行，而不是之后：如果顺序反了，一旦删除成功而导出失败，
恢复途径就没了。
