# [Feature] 世界书的默认扫描深度，资源中心与会话设置分别可看可调

### 这个能力解决什么问题？

世界书

每本世界书都有一个**整本的默认扫描深度**（World Info JSON 里的 `scan_depth`）——
没有自己填扫描深度的条目，用的就是它。这个值一直被正确保留、也真的在参与激活判断，
但**界面上从头到尾看不见，更改不了**。

条目级的扫描深度已经能在会话设置里改了，整本的这个反而没有入口：想把一本书
从「扫全部历史」收紧成「只扫最近 3 条」，只能回去改 JSON 文件再重新导入。

### 期望的行为

两个地方**分别**可以查看和调整，而且改的不是同一个东西：

| | 改的是 | 影响 |
| --- | --- | --- |
| **资源中心** | **世界书本身** | 以后所有新会话；绑定它的角色卡一起跟上 |
| **会话设置** | **只有这次会话的快照** | 只有当前这一局 |

### 补充：为什么「分别」这件事本来就成立

这两个地方本来就是两层东西，不是同一个设置的两个入口：

- 资源中心改的是**来源文件**。世界书 id 是内容的 sha256，所以改扫描深度和改正文
  一样会铸一个新 id，绑定跟着搬。
- 会话设置改的是**会话自己的覆盖层**。会话启动时把世界书冻成了无损快照，
  之后再也不读资源库；覆盖层只是叠在那份快照上。

所以「在资源中心改了，正在玩的那局不会变」不是妥协，是这两层各自该有的行为。

### 补充：三种状态，不是两种

整本扫描深度有一个容易被做丢的状态。会话这一层其实有**三种**情况：

1. **没有覆盖** —— 跟着文件走（文件本身也可能没写）
2. **覆盖成 N** —— 这次会话用 N
3. **覆盖成「没有」** —— 这次会话**主动取消**了文件里的默认深度

第 3 种和第 1 种的结果完全不同：文件写着 `scan_depth: 3`，第 1 种是扫 3 条，
第 3 种是扫全部。所以覆盖记录**存在与否**本身就是信息：记录在、里面没有
`scanDepth`，意思就是「这次会话不设整本深度」。

界面上对应「应用」（空着＝不限制）和「跟随文件」两个动作。

### 补充：提交时机

这个输入框**不是边打字边提交**的。会话覆盖层是一条只能追加的命令日志，
每个按键提交一次的话，打「100」会写三条命令，而且后两条会撞上自己的 revision 检查
直接报「世界书已在别处改变」。

所以沿用手动上限那一栏的做法：本地草稿 + 一个「应用」按钮，值没变时按钮是禁用的。
