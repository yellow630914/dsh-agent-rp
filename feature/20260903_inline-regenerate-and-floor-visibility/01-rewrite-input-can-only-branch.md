# [Feature] 修改输入后希望就地重新生成，而不是只能另开分支

### 这个能力解决什么问题？

回复版本 / 对话编辑

回合尾的「修改输入」目前只有一种结果：`prepareAgentRpRewriteSession()` 把
`events.slice(0, turnStart.seq)` 当成新会话的 seed，创建一段标题带「· 改写」的
**新会话**，原会话一个字节都不动。

这个语义其实是「从这一轮之前分岔」，不是「修改」。玩家想要的常常是另一件事：
就在当前这段对话里把刚才那句话换掉，让角色重新回答一次，不要多出一段新会话，
也不要留着那条回答旧问题的回复。

### 期望的行为

在**最后一轮**提供「修改输入并重新生成」：

- 就地替换这一轮的用户消息
- **直接丢弃现有回复**，不保留为可切换的版本
- 用修改后的输入重新生成一次

原有的「另开分支」保留，任何已完成回合都还能用。

### 已确定的策略

1. 就地重新生成**只给最后一轮**使用
2. 旧回复**不保留版本**，直接从上下文里去掉
3. 本轮已经沉淀的状态（MVU、Tavern 变量、消息注记、插图、故事工程）
   **不要求跟着回退**，但要让玩家知道

### 现有的相关实现

- `tavern-chat.ts` 的 `setMessages()` 已经在替换表层上的用户消息
  （酒馆脚本的 `setChatMessages`），而且 `appendEntry()` 对 user 角色写的是
  `source: { kind: 'user' }`，所以替换后的文字仍然会被 `visibleDialogue()` 看见，
  世界书扫描与预设组装不受影响
- `generation.ts` 的 `regenerate` 已经有完整的「发指令 → 等 `whenIdle()` →
  取新回复 → 收敛表层」流程，以及 `mvuBeforeReply()` / `readTavernHelperStateSnapshot()`
  这套回合起点状态基准

所以这个能力是把两个既有动作串起来，不需要新机制。

### 需要注意的约束

**只有最后一轮能做。** `latestReply()` 明确拒绝非末尾回复
（`只能操作对话末尾的角色回复`），而「修改输入」目前任何回合都能点，
因为分岔不需要末尾。两个动作放在同一个菜单里，必须让「哪个能用」一眼可见。

**语义从无风险变成破坏性。** 现行 rewrite 的最大优点是原会话不动；
就地重生会改写历史。这一点没有技术解法，只能在界面上讲清楚。

**必须 agent idle。** `AgentStatus` 只有 `'idle' | 'running'`；
`generate()` 开头检查 `agent.status !== 'idle' || agent.inbox.hasPending`。

### 补充：采用的实现

新增 `rewrite-input` 操作，走既有的 `/rp-generation` 命令：

1. 验证该回复是**表层最后一个节点**，否则拒绝
2. 从回复往前找到本轮的用户消息，把 **[用户消息 … 表层末尾]** 整段用一条新的
   `user/message` 取代 —— 旧回复连同本轮放到表层上的 notice、工具结果一起被遮蔽
3. 还原本轮开始时的 MVU / Tavern 基准，与 `regenerate` 用同一组函数；
   否则新回复会叠在那条已经删掉的回复留下的状态上
4. 用一条专属指令生成：「玩家修改了消息，当成第一次回复它，不要提及修改、
   不要延续任何更早的回复」
5. 失败时把原用户消息与原回复都放回表层，并还原状态后抛出

**不写 `agent-rp/generation-state`**，所以这一轮不会产生版本群组。
理由：版本群组装的是「同一条消息的不同答案」，输入改了之后旧回复回答的是一条
已经不存在的消息，放进版本列表只会让「切回上一版」产生语义错位。

「删除」在这里是表层遮蔽：Session log 只追加，原始事件仍在文件里
（`session-repair` 还救得回来），只是模型和界面都看不到。这是这个架构下唯一
能做的删除。

### 补充：界面

更多操作菜单变成两项：

| 菜单项 | 可用条件 |
| --- | --- |
| 修改输入并重新生成 | 最后一轮、且 regenerate 可用（含 Host 插件事件能力检查） |
| 修改输入并另开分支 | 任何已完成回合（原行为不变） |

同一个编辑框按模式切换说明与按钮文案。就地重生那个模式明确写出：旧回复不会
保留为可切换版本、本轮已沉淀的状态与插图不会跟着回退——策略 3 说不要求回退，
但不能让它变成沉默的意外。
