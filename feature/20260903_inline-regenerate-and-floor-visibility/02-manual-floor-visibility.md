# [Feature] 会话设置里主动隐藏楼层，并看清哪些楼层还在上下文里

### 这个能力解决什么问题？

上下文管理 / 会话设置

对话变长之后，玩家没有任何界面途径知道「这一轮到底把哪些楼层送进了模型」，
也没法主动把前面那些不再需要的楼层移出上下文。

`/hide` 已经存在，但只有酒馆脚本或卡片前端触发得到
（`client/index.tsx` 用正则拦 `/hide N-M` 再发 `set-chat-hidden`），
玩家自己碰不到，也看不到结果。

### 期望的行为

会话设置新增一个「楼层」面板：

- 列出**当前纳入上下文的楼层**与**已经被隐藏的楼层**
- 每层只要前几十个字的摘要就够，不需要正文
- 能主动调整隐藏范围

### 已确定的策略

1. **沿用既有的前缀隐藏逻辑**，不改持久表示法；界面做成滑杆，只能从最前面开始隐藏
2. 缩小隐藏范围（例如 20 层 → 10 层）可以用「先全部恢复、再隐藏 10 层」实现
3. **可以接受恢复是有损的**，也可以接受世界书扫描窗口跟着改变
4. 滑杆拖动**不提交**，按「确定」才生效

### 现有实现的形状

隐藏的做法是把消息**从 DSH 表层移除**（`rewriteSurface`），文字留在
`hiddenPrefix` 里供脚本读取。所以「隐藏」= 真的不进模型上下文，正是需要的效果。

但 `setHidden()` 有两道写死的限制：

```ts
if (request.start !== 0 || request.end >= total) throw new Error('当前仅支持从第 0 楼开始隐藏或恢复')
if (request.end < hiddenPrefix.length - 1)       throw new Error('当前需要一次恢复全部隐藏前缀')
```

只能从第 0 楼开始隐藏、只能一次全部恢复。数据结构本身就叫 `hiddenPrefix`，
是前缀数组而不是每条消息的标志位。策略 1 选择接受这个形状，所以这次不动它。

展示所需的数据大部分已经在：`projection.tavern.messages` 是
`[...hidden(isHidden:true), ...visible(isHidden:false)]`。但它有两个问题：

- 只在 `state.tavern !== undefined` 时才存在，**没碰过酒馆状态的会话拿不到**
- 带的是每条消息的**完整正文**，每次投影更新都整份送到浏览器

### 已知代价（都在策略 3 的接受范围内）

**恢复是有损的。** `setHidden()` 恢复时把隐藏消息重建成 `kind: 'synthetic'` 的
新事件，原 assistant 事件身份没了。

**连没被隐藏的楼层也会拿到新 seq。** `rewriteSurface()` 第一个节点用
`replace(整段)`、其余全部 `append`，所以每次隐藏或恢复都会重新追加整个表层。
挂在旧 seq 上的回复版本、消息注记、该楼层的生图关联都会对不回去。

**每次调整的事件成本 ≈ 剩余可见楼层数。** 以 300 条消息的会话估：

| 操作 | 追加的事件数 |
| --- | --- |
| 隐藏前 20 层 | ≈ 280 |
| 全部恢复 | ≈ 300 |
| 再隐藏前 10 层 | ≈ 290 |
| 20 → 10 合计 | ≈ 590 |

这是策略 4 的直接原因：滑杆若边拖边提交，拖过二十格就是十几次全表层重写。

### 补充：采用的实现

**投影**新增 `floors`：每层带 `seq / role / preview（40 字）/ hidden`，隐藏的排前面。
它**不依赖酒馆状态**（从 `state.surface` 与 `tavern?.hiddenPrefix` 组合而成），
而且只带摘要，不重复 `tavern.messages` 那份正文——这份列表每次投影更新都会
送到浏览器，所以刻意做成便宜的。

**界面**：会话设置 →「楼层」。滑杆设定隐藏最前面几层，上限是「总层数 − 1」
（至少留一层让角色能接话）；下方列出全部楼层，被划掉的就是这次会隐藏的。
拖动只更新本地预览，按「确定」才提交。

**提交逻辑**沿用既有的 `set-chat-hidden`，Host 端一行没改：

- 目标 < 当前：先 `hidden:false` 整段恢复，再 `hidden:true` 隐藏目标层数
- 目标 > 当前：直接 `hidden:true`
- 相等：不发请求

### 补充：没有做的部分

**任意楼层隐藏**没有做。那需要把 `hiddenPrefix` 从前缀数组换成位置化的表示，
连带修改所有 `message_id - hiddenPrefix.length` 的索引换算
（`tavern-chat.ts` 的 set / create / delete / rotate 四条路径）、
`projection.ts` 的 `[...hidden, ...visible]` 拼接，以及 `tavern-helper.ts` 的解析。
`validateRepresentable()` 里那句
`DSH 会话暂时不能保留但隐藏一条卡片脚本聊天楼层` 就是这个表示法缺口的记录。

**部分恢复**没有做。放宽 `setHidden()` 的
`if (request.end < hiddenPrefix.length - 1)` 守卫、允许只恢复前缀尾部的 K 条，
能把 20 → 10 的成本砍掉一半，也少一次「全部恢复」造成的身份重建。
这是一个小而收敛的改动，值得作为后续项。
