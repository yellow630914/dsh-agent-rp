# 需求：状态数据脱离 MVU，状态栏用可自定义模板呈现

## 起因

回合后的状态结算已经有了——`state-settlement` Worker 在角色正文结束后跑候选加独立核验，
两段请求都写进 Session，可重放。但它**只在 SillyTavern 变量卡上生效**：
`stateActions` 要非空，必须同时满足 `turnMode === 'agent'`、会话有 MVU 状态、
且世界书里有「变量更新规则 / `<UpdateVariable>`」条目。

也就是说，一个没有导入变量卡的原生会话，这个 Worker 永远 `skipped`。
状态能力实际上被一个外部格式的世界书条目绑架了。

状态栏同样：它读 `projection.mvu.statData`，模板来自角色卡前端，
呈现方式改不了，玩家也放不进自己的模板。

## 要求

1. **状态数据与 MVU 体系脱钩**，不依赖世界书条目、不依赖任何外部脚本
2. **原生会话也要有回合后状态结算**
3. 状态数据仍然**用 JSON 存**；呈现层可自定义
4. 资源中心可以保存设计好的**状态栏模板**（html / md / 纯文本）
5. 打开状态栏时**先渲染模板，再把对应路径的 JSON 填进去**
6. 设置 → Agent 工具策略里可以选**是否每回合触发**
7. 对结果不满意时可以**手动重跑**
8. 状态栏**做成可折叠**，保持在输入框上方

## 不在范围内

- 把状态本体换成 Markdown 存储（模板是展示层，JSON 仍是唯一 canonical）
- 第二套状态结算管线（手动重跑必须复用同一个 Worker 函数）
- 让模板执行 JS（那等于把外部脚本请回来）
- 状态栏放到右侧（DSH 没有右栏 slot，浮层抽屉留到以后再说）

## 必须守住的边界

### 模板不能回流到模型可见层

模板只读投影，**不进** `renderRoleplayStateContext`，**不进**结算 evidence。
否则玩家改一个模板就改了重放结果。

### 可后改与不可后改

| | 能不能事后编辑 | 为什么 |
|---|---|---|
| 状态栏模板 | **能** | 展示层，旧会话重开照样套新模板 |
| 状态 schema | **不能** | 模型可见，必须冻结成 seed 事件 |
| 结算规则 | **不能** | 同上 |

### 不能影响楼层与聊天记录

Worker 写的全是 plugin 事件，没有 `surfaceOp`，五层投影都看不见它们。
工具路径的 `tool/result` 会进第 1、2 层，但 `surfaceRole()` 对它返回 `undefined`，
所以 `floorProjection` 和 `visibleTavernMessages` 都会滤掉它——
**楼层编号和酒馆 `message_id` 不会错位**。

验收要有一条回归钉死这件事：结算前后 `floors`、`tavern.messages` 的 `messageId`
序列必须逐一相同。

### 手动重跑的基线

结算用 `expectedRevision` 做 CAS。上一次结算成功后状态已经前进，
若从**新状态**重算，`delta` 会被套用两次。所以重跑必须**从同一个基线开始**：
先追加一笔把值还原到结算前，再从那里重算。SessionLog 只能追加，
所以是「再追加一笔」而不是「撤销」，revision 继续往上走。

还有：`visibleReplyText()` 用 `foldSurface()`（第 1 层）取正文，
但回复版本切换走的是第 3 层 overlay，`foldSurface` 不认。
手动重跑必须改读 `roleplaySurfaceNodes()`，否则玩家切回旧版本后重算，
读到的不是画面上那一版。

## 分步

| | 内容 |
|---|---|
| 1 | 原生状态方案：schema + 结算规则 + 模板引用，冻结成 seed 事件 |
| 2 | 结算脱钩 MVU，原生会话启用 |
| 3 | 资源中心状态栏模板库（html / md / txt） |
| 4 | 模板渲染器：声明式 JSON Pointer 占位符 |
| 5 | 工具策略 `stateMode` 四值 |
| 6 | 手动重跑（重新渲染 / 重新结算两段式） |
| 7 | 状态栏可折叠 |

Step 1–4 完成前，MVU 会话走旧路径完全不受影响。
